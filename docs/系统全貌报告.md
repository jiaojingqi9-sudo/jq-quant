## 0. 一句话结论（已核对）

你做的不是"一个交易脚本"，而是**一整套个人量化交易工作台**：两套独立的交易引擎（一套成熟的 `taa_futu`，一套更早的 `claude_trade` 被前者当子策略调用）＋ 一个独立的新闻情报系统 ＋ 一个把这些串起来的"富途邮差"后台服务 ＋ 控制台/看板 UI ＋ 一套带审计账本和"自动学习"的工程化底座。

它的成熟度其实**远高于**一般 GitHub 上的"量化玩具"：有事件溯源账本、双分录＋哈希链审计、下单前硬风控、看门狗、自检 Doctor、以及一个**故意不闭环**的策略学习实验室。你缺的不是功能，而是**一张地图 + 工程化收尾 + 把学习成果接回策略的最后一段**。

## 4. 自动学习闭环的真相（已核对——这是你最关心的一块）

**结论：学习环是"真的在跑、有真实数据、但最后一段故意没接上"。**

它做了什么（股票/加密/新闻三套各一份）：
1. 记录每笔下单决策（`*_order_memory.jsonl`）；
2. FIFO 配对算出已实现盈亏并打标签（`profitable / fees_dominated / signal_error / low_edge_trade ...`）；
3. 按策略/标的/原因聚合归因（`*_attribution.json`）；
4. 生成**研究级改进候选**（`*_upgrade_candidates.jsonl`，如"把最小单金额从 500 提到 750"）；
5. 过**晋级门禁**（`*_promotion_report.json`）；
6. 产出可发给 Codex 的**复核包**（`*_review_packet.md/.json`，带 SHA-256 证据哈希）。

**为什么"不回写"——这是设计，不是 bug（已核对）：**
文档明写 `live_auto_promotion = false` 永远成立，`cannot edit strategy code`。理由是防过拟合、防把没经过 walk-forward / purged 验证 / 成本压力 / 纸面交易 / 人工审批的参数，直接推到真金白银上。这是**专业做法**，不是缺陷。

**真实数据现状（subagent 核对，line count 实测）：**

| | 股票 | 加密 |
|---|---|---|
| order_memory | 4,778 行 ✅ | 18,620 行 ✅ |
| trade_outcomes | 940 行 ✅ | **0 行**（没成交过）⚠️ |
| 候选 | 5 个（含"最小单 500→750"） | 3 个，全被"样本<30"挡住 |
| 晋级到 live | `live_allowed=false` | `false` |
| 最后构建时间 | 2026-05-15（**已 18 天未更新**） | 2026-05-15 |

**缺口（这就是你说的"把学到的东西并进策略"要补的那段）：**
`config.py` 的 `load_settings()` **只读 `.env`**。全系统**没有任何代码**去读 `promotion_report.json` 或 `upgrade_candidates.jsonl` 来更新参数；也没有任何 `overrides.json / promoted_params.json` 这类文件。所以学习成果目前停在"生成建议"，**人不手动改 `.env` 就永远不生效**。

> 补这段的**正确方式**不是"让 AI 自动改 .env"，而是做一个**人审批后的版本化参数晋级桥**：候选 → 门禁 → 你点头 → 写入一个 `promoted_overrides.json`（带时间戳/理由/来源候选 id）→ 策略加载时叠加这层 override（live 仍需显式开关）。这恰好是简历上最值钱的一块："我做了一个带 human-in-the-loop 审批的策略自进化闭环"。

## 5. 新闻情报系统 C：`market_news`（subagent 核对）

独立的 MVP，DDD 分层（domain / application / infrastructure / services）：
- **抓**：CNINFO、SEC、HKEX、东方财富、路透、新华、微博、雪球等 ~15 源（A股/港股/美股）。
- **处理**：归一化 → 去重 → 事件聚类（Jaccard 0.35）→ 影响打分（配置驱动）→ 标的排名。
- **推**：通过本地 OpenClaw 把高优先级提醒发到手机；产出 JSON/Markdown/HTML 看板。
- **运维**：launchd 5 条常驻线（collect/notify/health/news-learning/review-api），自带健康自愈。
- **也有自己的学习环**（news_learning，证据→复核包）。
- **与 A 解耦**：零导入耦合，只有可选的"富途数据增强"开关。
- **红旗**：launchd plist 里**硬编码了 `/Users/<用户名>/All here/news collector`** 绝对路径，换机器会废。

## 6. 富途邮差 D：`futu_watcher`（subagent 核对）

一个 launchd 常驻服务 `com.jiao.futu-watcher`：
- 轮询 `futu_queue/` 里的 `*.task.json`，按 `skill` 字段分派（snapshot / account / option / intraday / **live_signal**）；
- `live_signal_proxy.py` 把任务桥接到 `taa-futu live-signal` 子进程，回写 `*.result.json`；
- `futu_queue/` 和 `futu_output/` 是运行时输入输出目录，不是源码。
- **红旗**：根目录一堆 `.command` 脚本和 plist 里**硬编码 `/Users/<用户名>/All here/...`**，不可移植。（trade 侧已于 2026-07-24 全部改为相对路径）
