# 下单练习台（Execution Trainer）

用自己收集的真实盘口数据标定出一个合成市场，在上面练大单执行，
收工后按「你不在场的那个市场」的成交均价打分。

接进外壳的方式和新闻页一样：`src/taa_futu/features/exec_trainer.py` 登记一个
Feature，侧边栏出现 **🎯 下单练习 / Execution Trainer**。不依赖 OpenD、
不连实时行情，永远可用。

---

## 一分钟上手

1. 打开工作台，侧边栏选「下单练习」
2. 设任务：方向 / 股数 / 限时 / 几点开始 / 一回合多少秒 / 行情编号
   开局页会实时算出**参与率**并标颜色——那是难度的唯一来源
3. 每回合决定下什么单，按「下一回合」推进市场
4. 「收工并评分」出成绩单

默认 100 万股 / 1 小时 / 10:30 开始 ≈ 5% 参与率。想要真难就调到 200–300 万股。

**换个「行情编号」就是另一天的行情**，同一个编号永远复现同一天——
方便拿同一天行情比较不同打法。

## 模块

| 文件 | 干什么 |
|---|---|
| `book.py` | 订单簿与撮合。价格优先、同价先到先得。支持冰山单（`display` 字段）和 IOC |
| `market.py` | 合成市场引擎。做市商 + 机构被动单 + 噪音/价值/动量三类机器人 |
| `session.py` | 一局练习：任务定义、下单接口、影子市场基准、收工评分 |
| `panel.py` | Streamlit 界面 |
| `calibrate.py` | 从 `runtime/market_data/*/lob.jsonl` 量盘口形状（单日） |
| `calibrate_volume.py` | 从 `klines.jsonl` 量成交量与日内曲线（单日 + merge） |
| `merge_calibration.py` | 多天盘口标定合并成市场性格档案 |

界面只跟 `Session` 打交道，引擎和界面是分开的——写一个自动策略跑批量回测，
直接调 `Session` 就行，不用碰界面。

## 三件设计上要紧的事

### 1. 评分基准是「影子市场」，不是区间 VWAP

同一个种子、同一段时间、**但你没进场**的那个市场，它的成交均价就是基准。

不用区间 VWAP 的原因有两条，第二条更要命：

- 你占了一成成交量，基准就被你自己的成交价拉过去一成
- 你把行情推走的那部分（冲击、信息泄露）会**同时推走基准**，等于完全测不到

模拟器有真实 TCA 没有的条件：可以把「你不在场的那个世界」原样跑一遍。
行情涨跌两边一模一样，减完剩下的纯粹是你留下的脚印。

为了让影子市场成立，价格过程按**固定时间网格**推进（0.25 秒一步）、不跟着事件走——
跟着事件的话，你多下一张单就改变了随机数的消耗顺序，两次跑出来根本不是同一天。

### 2. 盘口显示的量只是一部分

标定实测：**65% 的时候最优价那一档是碎股**（11 股、88 股这种），
而整手第一档中位数是 258 股。同时官方日线说 NVDA 一天成交 1.345 亿股。
几千股的可见盘口撑不起每秒五千多股的成交——差额只能是没显示出来的。

所以订单簿里 `qty` 是真实剩余量、`display` 是盘口上露出来的，撮合和排队按
`qty` 全额算。做市商每档真实挂 6 倍于显示量，另有一类**完全不显示**的机构被动单。

界面上会告诉你「排我前面 654 股」——那些是盘口上看不见的。
**看着「才一百多股，马上轮到我」就一直等下去，是做大单最常踩的坑。**

### 3. 露量是要付代价的

在盘口露出超过该档平常厚度两倍的量，别人会抢在你前面挂高一个 tick——
反正你还得接着买，他挂在你前面稳赚。结果是你排在后面成交不了，只能追。

解药是**冰山单**：下单区的「盘口只显示」输入框。露得少别人看不见，
代价是排队照全额排、不会成交得更快。实测同样打法，全露 2.4bp、只露 200 股 0.9bp。

## 重新标定（换标的或补新数据时）

标定分两条线，因为两个数据源的可信度差很远：

```bash
# 1. 盘口形状（价差、各档深度、波动率、收益分布）——用 lob.jsonl
python src/taa_futu/exec_trainer/calibrate.py 2026-08-04 US.NVDA   # 逐日跑
python src/taa_futu/exec_trainer/merge_calibration.py US.NVDA      # 合并

# 2. 成交量与日内曲线——用 klines.jsonl
python src/taa_futu/exec_trainer/calibrate_volume.py 2026-08-04 US.NVDA
python src/taa_futu/exec_trainer/calibrate_volume.py merge US.NVDA
```

产物在 `runtime/exec_trainer/`（被 gitignore）：

| 文件 | 内容 |
|---|---|
| `US_NVDA_market_profile.json` | 盘口形状 + `realism_targets`（验收用） |
| `US_NVDA_volume_profile.json` | 日内成交量曲线 |
| `US_NVDA_official_volume.json` | **官方日线成交量**，手工从接口取，见下 |

`official_volume.json` 是**总量的权威来源**。本地 1 分钟 K 线累加只有官方的 68%，
不能当总量用（只能用来算日内曲线的**形状**）。刷新方法：邮差 `{"skill": "nvda_volume"}`
（脚本在 `futu_watcher/nvda_volume_official.py`，不在本仓库）。

档案不存在时引擎回落到代码里写死的默认值——那也是同一批数据的中位数，
但界面会挂一条警告提示你去标定。

## 验收标准

对齐 JP Morgan AI Research, *Get Real: Realism Metrics for Robust Limit Order
Book Market Simulations*（arXiv 1912.04941），6 大类 26 项真实性指标。
当前对得上的（3 个种子 × 1 小时）：

| 指标 | 实测目标 | 合成市场 | |
|---|---|---|---|
| 价差 1/2/3 tick | 16/36/30% | 16/37/29% | ✅ |
| 5 分钟已实现波动 | 0.272% | 0.286% | ✅ |
| 每秒成交量 | 5,087 | 4,935–4,999 | ✅ |
| 收益线性自相关 | ≈0 | −0.07~+0.03 | ✅ |
| 绝对收益自相关（波动率聚集） | 0.228/0.188/0.166/0.134 | 0.235/0.227/0.211/0.151 | ✅ |
| 峰度（1 秒） | 11.5 | 7.4 | ⚠️ |
| 逐档深度误差 | — | 11–13% | ⚠️ |

Get Real 26 项里**这份数据支持不了**的项（订单寿命与到达间隔分布、新订单价格
分布、跨资产相关性、宏观事件敏感性、订单流时间相关性）在 v3 文档第五节列明，
不冒充全项通过。

## 三个踩过的测量坑

改标定脚本之前先读这一节，这三个错误都很隐蔽，而且都会让结果看起来很合理：

1. **碎股当一档**：最优价 65% 是碎股。含碎股口径量出买一 125 股、价差 1 tick 占 40%；
   整手口径是 258 股、16%。依据不只是「量小」——OFR 工作论文 25-01 实测碎股流动性
   在大单成交前「不到一毫秒内消失」，那些量根本吃不到。
2. **成交量口径**：1 分钟 K 线累加只有官方日线的 68%。总量必须用官方日线。
3. **混采样间隔**：数据只覆盖盘中 20% 的秒。把间隔 0–30 秒的收益混着算再除以
   平均间隔，**光是混合本身就会造出肥尾**——同一天算出峰度 238，严格 1 秒是 42.9。
   所以 `calibrate.py` 里有 `DT_MIN/DT_MAX`，间隔不在窗口内的相邻对整对丢弃。

## 已知的软处

1. 峰度和逐档深度离散度两项没达标（原因见 v3 文档）
2. **纯挂单的打法仍然偏容易**：抢价机制目前是「过阈值就固定 3 个 tick」的开关，
   该改成随露出量连续加码
3. **没有集合竞价机制**：收盘竞价那一笔（占全天 28%）被摊成连续流量
4. **离券商终端还差一块**：算法单（TWAP/VWAP/POV/IS）、母单子单视图、
   活动委托列表、实时 TCA 面板
