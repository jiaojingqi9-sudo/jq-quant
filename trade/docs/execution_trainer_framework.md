## 零、一句话结论

**TraderEx 可以复刻。** 它的市场模型在 Schwartz / Sipress / Weber 的教材里是公开的，
不是黑箱：一个隐藏的均衡价 P\*（跳跃过程）+ 泊松订单流 + 三类机器交易者。
引擎本身几百行 Python 就能写完，难的不是它，是**把它和我们自己的真实盘口数据接在一起**。

---

## 一、这个东西是干什么的

给一个大单任务（例如「10:00 前买满 5000 股」），你手动决定怎么拆、什么时候挂、什么时候吃，
结束后按机构口径打分，并跟机器基准比高低。**练决策，不练手速**，所以做回合制。

系统要能在**两种市场**上练，因为两者各缺一半：

| | 合成市场（复刻 TraderEx） | 真实回放（我们自己的数据） |
|---|---|---|
| 市场从哪来 | P\* 驱动的机器订单流生成 | 108 个交易日的真实盘口快照 |
| 会不会对你有反应 | **会**。你吃掉一档，机器会补、会追 | **不会**。市场是录像 |
| 真不真实 | 结构真实，数值是编的 | 数值真实，行为是死的 |
| 练什么 | 冲击、抢跑、被吃穿的代价 | 真实的价差、深度、一天的节奏 |
| 成本数字可信度 | 相对可信（有反馈闭环） | 只有相对值可信 |

**成熟形态是两者合一**（见第七节 M3）：真实盘口打底，合成引擎负责「你动了之后市场怎么补」。

## 二、TraderEx 复刻规格

以下来自公开教材与 2026-08-04 实际跑一局的观察，可直接照着实现。

### 2.1 均衡价 P\*

- 一个**隐藏的真实价值**，玩家看不到（教师端能看到、能手动推）。
- 按**跳跃过程**演化：两次跳跃之间的间隔从一个统计分布里随机抽，跳跃发生时价格不连续地移动。
- 跳跃频率和幅度＝**波动率参数**。
- 教师端可以随时 Increase / Decrease P\*，用来制造「突发消息」。
- 实测：一局开始 P\* = 27.5，跑到尾盘 P\* = 27.65。

### 2.2 订单到达：泊松过程

- 订单到达是**无记忆的**——下一秒来单子的概率跟已经等了多久无关，玩家没法靠节奏预测。
- 到达**速率**取决于市场报价与 P\* 的关系，这是整个模型的自平衡机制：
  - 市场价高于 P\* → 卖单到达率上升、买单下降 → 价格被压回去
  - 市场价低于 P\* → 买单到达率上升、卖单下降 → 价格被托回去
- 订单大小从统计分布里抽。

### 2.3 三类机器交易者

| 类型 | 行为规则 | 作用 |
|---|---|---|
| **知情者** | 知道 P\*。P\* 高于市场卖价就发市价买单；P\* 低于市场买价就发市价卖单。**当 P\* 跑到买卖价之外时，市价单占总订单流的比例从约 50% 提高到约 70%** | 价格发现，制造趋势 |
| **流动性交易者** | 双边、随机、跟价格无关（自己要用钱），限价单市价单都发 | 提供噪音与深度 |
| **技术交易者** | 追动量。**连续出现 4 笔以上同方向成交或中间价同方向跳动时，下一张机器单是同方向市价单的概率上升** | 制造趋势的自我强化 |

这三类的**比例可调**——这是制造不同市场性格的主要旋钮。

### 2.4 四种市场结构

| 结构 | 机制 | 优先级 |
|---|---|---|
| **连续订单簿** | 限价单挂出价格，市价单来了就撮合 | v1 必做 |
| **集合竞价** | 订单批量攒着，到点一次性以单一清算价成交 | M2 |
| **做市商市场** | 做市商报双边价，你只能跟他成交 | M2 |
| **暗池 / 大宗** | 无盘前透明度，大单撮合或协商 | M3 |

**混合结构**（连续订单簿 + 暗池、连续 + 竞价）是高级练习的核心——练**去哪儿成交**，
而不只是**什么时候成交**。

### 2.5 评分：四项合成

TraderEx 不是只看一个数，而是四项加权：

1. **P&L**——已实现 + 未实现（按市值计）
2. **VWAP 执行质量**——你的均价 vs 市场 VWAP（买方低于 VWAP 算赢）
3. **风险分**——完成过程有多稳，跟一条基准执行节奏比
4. **任务完成度**——收盘时完成了任务量的百分之多少

**权重按练习目的调整**。这一条很重要：练执行成本时 VWAP 和完成度权重高，练做市时 P&L 权重高。
**没有单一分数**，防止用一个指标钻空子。

### 2.6 情景可复现

- 情景编号 1–100 决定随机种子。**同一个编号 = 同一个市场**，只有你的决策不同。
- 这是整个教学法的关键：**一次只变一个变量**——同样的行情，换个策略再跑一遍，直接对比。

### 2.7 教师端旋钮

情景编号 / 波动率（P\* 跳跃频率与幅度）/ 流动性（到达率与订单大小）/ 时长 /
任务（买还是卖、多少量）/ 消息时点 / 市场结构 / 三类交易者的比例 /
运行中：Thicken Book、Thin Book、Increase P\*、Decrease P\*。

### 2.8 界面（实测）

- 顶部：模拟时钟（09:30 → 16:00）
- 状态条：Shares / **Mission: Buy 500** / Cash / P&L / Average Pos / **Average Buy** / Average Sell / **Market VWAP** / Last Price / Market Vol
- 主区：价格阶梯五列 `我的限价买 | 市场买量 | 价格 | 市场卖量 | 我的限价卖`，
  每行一个价位（5 分一档），两边输入框挂单、× 撤单，Center 按钮把视窗拉回最优价附近
- 右侧：K 线图（含前几日）+ 成交流水（时间 / 量 / 代码 / 方向 / 价）
- 参与者面板：solitaire 只有自己；network 列出所有人和各自任务

## 三、我们要改的地方

1. **档位密度**：TraderEx 5 分一档、盘口几十到几百股；我们的真实数据 1 分一档、每边 60–105 档、
   动辄上万股。价格阶梯必须能折叠远端档位，默认显示最优价上下各 8 档。
2. **一局的长度**：TraderEx 一局是一整个交易日；我们一局是一个**执行窗口**（30–60 分钟）。
   练执行，不练选时。
3. **回合制而不是实时**：Streamlit 每次交互整页重跑，做「每 0.5 秒推一帧还能随时下单」会很难受
   （新闻页刚踩过这个坑）。点「下一步 N 秒」推进，期间挂单按规则结算。
   副作用是好的：练习本来就该能停下来想。
4. **真实回放模式里没有 P\***——市场是录像，不需要生成器。P\* 只在合成模式和混合模式里存在。

## 四、数据底座（已实测，非估计）

来源 `trade/runtime/market_data/<交易日>/`：

| 文件 | 实测情况 | 用途 |
|---|---|---|
| `lob.jsonl` | 8 只美股；盘中每标的 **0.03–0.30 秒一张**；每边 **60–105 档**（盘前 60）；每档 `[价格, 量, 委托笔数, {}]` | 回放主力 |
| `snapshots.jsonl` | 141 字段，含累计 `volume` / `turnover` | 差分算真实区间 VWAP |
| `ticks.jsonl` | **覆盖率约 17%**：每轮取最近 50/100 笔、覆盖 0.63s，采集间隔 3.74s，相邻批次 88% 有缺口。3 月到 8 月各抽一天**每天都在漏**（连续率 22%–77%） | 只能参考 |
| `klines.jsonl` | 1 分钟 K 线，完整 | 背景图 |

**标的**：QQQ、NVDA、AMD、TSLA、META、COIN、MSTR、AAPL
**可用交易日**：108 天（2026-03-11 → 08-04）。5/19 之后是 60 档那一代，质量最好；4 月 40 档；3 月 3 档。
**已知缺陷**：美股「委托笔数」恒为 0（富途只在港股给）→ 队列里有几笔不可知，只知道总量。

## 五、模块划分（插件式，跟新闻页一样插进 app）

```
trade/src/taa_futu/
  features/execution_trainer.py      # 插件注册：一个文件就多一页
  exec_trainer/
    market/
      replay.py          # 引擎A：真实盘口回放
      synthetic.py       # 引擎B：TraderEx 复刻（P* + 泊松 + 三类交易者）
      hybrid.py          # 引擎C：真实打底 + 合成补反应（成熟形态）
      structures.py      # 连续订单簿 / 集合竞价 / 做市商 / 暗池
    matching.py          # 撮合：我的单子这一帧成交了多少
    task.py              # 任务、剩余量、剩余时间、硬约束
    scoring.py           # 四项评分与合成
    algos.py             # 机器基准 TWAP / VWAP / POV / IS
    scenario.py          # 情景种子、参数集、可复现
    ui.py                # 价格阶梯 + 状态条 + 成绩单
```

两个引擎实现**同一个接口**（`step(dt)` → 新盘口 + 新成交），所以撮合、评分、界面完全共用。
不改任何现有模块，数据只读。

## 六、撮合规则

### v1（简化，先跑起来）

- **主动吃单**：按当前快照逐档吃，吃到哪档算哪档的价。**这部分完全真实**，60–105 档深度足够。
- **限价挂单**：下一帧市场最优价**穿过**你的限价就算成交，不看队列位置。
  **偏乐观**——真实情况你可能排在后面没轮到。成绩单必须把这一点写在脸上。
- **撤单**：立即生效。

### v2（队列位置）

进队时记下前面有多少量，之后按该价位的量减少推进你的位置；用 `snapshots` 的累计成交量差分
校准每个价位的消耗速度，弥补逐笔只有 17%。这是 L2 数据下的通行做法。

### v3（市场反应）

合成引擎接管「你吃掉的量怎么补回来」：补多快、补在什么价，由参数控制。
**做完这一步，绝对 bps 才开始有意义**。

## 七、成熟形态路线

### M1 · 能跑完一局（唯一必须做的）

真实回放 + 价格阶梯 + 主动吃单 + 三条机器基准 + 成绩单。
**完成标准**：随便抽一天一只票，跑完一个 30 分钟窗口，出成绩单。

### M2 · 能比出高低

限价挂撤单（乐观口径）· 四项评分合成 · 情景种子可复现（同一天同一段重跑）·
合成引擎第一版（P\* + 泊松 + 三类交易者，连续订单簿）。
**完成标准**：同一个情景跑两遍不同策略，分数可比；合成市场跑出来的价格序列，
其波动率和价差分布跟真实数据同量级。

### M3 · 像个真东西

混合引擎（真实打底 + 合成补反应）· 队列位置模型 · 集合竞价与做市商市场 ·
暗池与路由选择 · 参与率硬约束与警告 · 教师端旋钮（波动率、流动性、消息、交易者比例）。
**完成标准**：同一天同一段，你手动执行 vs TWAP/VWAP/POV，胜负关系稳定可重复。

### M4 · 变成训练体系

- **课程化**：一组固定情景，从易到难（平静市 → 单边趋势 → 突发消息 → 流动性枯竭）
- **成绩曲线**：记录每一局，看自己的滑点随练习次数怎么走
- **回放讲评**：一局结束后逐步回看，标出「这里该吃却在等」「这里追高了」
- **接实盘**：练出来的执行节奏，反过来变成 `auto_trader` 的下单策略参数

## 八、评分口径（TCA）

全部用 bps，**正数 = 比基准差**。

| 指标 | 算法 | 说明 |
|---|---|---|
| **到达价滑点** | (你的均价 − 父单下达时中间价) / 中间价 × 10000 | 最主要 |
| **VWAP 滑点** | (你的均价 − 区间市场 VWAP) / VWAP × 10000 | VWAP 用 `snapshots` 累计成交额差分 ÷ 累计量差分，是真值 |
| **TWAP 滑点** | 区间内所有快照中间价的简单平均 | |
| **被动成交占比** | 挂单成交量 ÷ 总成交量 | 高通常成本低，但完成风险大 |
| **参与率** | 你的成交量 ÷ 同区间市场成交量 | 超过 10–15% 现实中会显著推价 |
| **完成率** | 实际完成 ÷ 任务量 | **不完成重罚**，否则「一直等好价」是个假的高分策略 |
| **区间市场位移** | 区间末中间价 − 到达价 | 判断成本是你造成的还是行情造成的 |

**机器基准**（同一份数据、同一个窗口自动跑）：TWAP、VWAP（按当天分钟量曲线）、POV 10%。
成绩单最上面一行只说一句：你比这三条里最好的那条好 X bps 还是差 X bps。

## 十、已知风险与待定

1. **被动成交是信任瓶颈。** v1 的乐观口径会让你以为「多挂少吃」总是对的，
   而真实市场里挂了未必成交、没成交就得在末尾追高。成绩单必须标注口径。
2. **逐笔只有 17%**，v2 的队列模型缺校准数据。改订阅式采集能让**以后**的数据接近全量，
   历史 108 天补不回来。
3. **参与率的现实约束缺失**：回放里你可以吃掉整个盘口，现实中不行。
   v1 就加硬约束——单次吃单不超过当前可见深度的某个比例，超过给警告。
4. **合成引擎的参数要校准**：P\* 跳跃频率、订单到达率、订单大小分布，
   都应该从我们自己的 108 天真实数据里估出来，而不是照抄教材的默认值。
   这样合成市场才跟我们练的标的是一个性格。
5. **待定**：练习标的与单笔规模。规模决定难度，也决定参与率是否离谱。
